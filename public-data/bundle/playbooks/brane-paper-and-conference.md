# 전제

brane은 "학계 지표가 바탕이 되어야 하는" 제품이 아니다 — 벤치마크 불참이 공식 포지션
([brane 포지셔닝](../architecture/brane.md) 참조). 논문은 필요조건이 아니라 **신뢰 자산(back)**이다.

# 플레이북 선택

- **플레이북 A (MemGPT/Letta형, 논문 먼저): 기각.** 저자들이 연구자라 성립하는 경로 —
  남의 언페어 어드밴티지로 싸우는 셈이 된다.
- **플레이북 B (Mem0/Zep형, 제품 먼저 + 논문은 증폭기): 채택.** 논문 = 트랙션 이후의 마케팅 포탄.

# 발표처

- **IEEE 기각.** 저널 심사가 수개월~1년 걸려 이 판의 시계와 불일치.
- 채택:
  ① **arXiv 프리프린트** — 즉시 공개, 이 카테고리의 바이럴 채널.
  ② **ML 학회 워크숍**(NeurIPS/ICLR/ICML 에이전트 메모리 트랙) — 4~6p 포지션/시스템 페이퍼,
     non-archival, 학부생·인디 저자 통과 실례 있음, 마감 보통 늦여름.
  풀 컨퍼런스 본 트랙은 논외.
- 논문 제목 방향(추정, 확정 아님): "사람이 읽는 파일 번들로서의 에이전트 메모리 —
  N개월 실사용 사례 연구" (죽음의 테스트, 모순 vs 상세화 판정, 소크라테스 모드 = 실험 섹션 구상).
- 구조적 이점: 12월 게이트(편입)가 논문을 숙성시킨다 — "6개월 실사용"은 이 분야
  시스템 페이퍼에서 아무도 못 갖는 증거(연구자 실험은 수 주가 최대).

# 확정 시퀀스 (편입 이후 전부 개시)

1. 지금~2026-12: 편입 + 도그푸딩만 (= 논문 데이터 자동 축적).
2. 판정: 편입 후에도 매일 사용 중인가 → Yes면 Phase 1 자격.
3. Phase 1: CLI 실구현 (write path 코드화) — 첫 코드.
4. **동시 발사**: OSS 공개(Show HN) + 4p 포지션 페이퍼(arXiv+워크숍) — 같은 도그푸딩 데이터를
   빌더 커뮤니티와 연구 커뮤니티에 쏘는 두 발사대. GitHub 스타는 발사의 결과이지 선행조건 아님.
   공개 대상은 엔진 코드뿐 — 번들(두뇌)은 영원히 프라이빗.

# ICML 2026 판단 (2026-07-06~11, COEX 서울) — 플레이북의 첫 적용 사례

- 에이전트 메모리 워크숍(SCALE, MemAgents 등) 대거 편성 = brane 문제의식의 학계 검증 신호
  → brane 포지셔닝 자료 인용 근거로만 흡수.
- **본 컨퍼런스 네트워킹 = 불참 확정.** 근거: ICML의 통화는 논문 — 발표작·랩 없는 학부생
  신분은 잘못된 경기장에서 좋은 패("출시한 제품")를 들고 있는 것.
- 조건부 예외(보상 규칙): 평일 의무(편입 준비) 완료 + 주말 여유 시, 워크숍 반나절을
  "네트워킹"이 아닌 **"정찰"**(문제 지도 수집)로만. 준비물 = 도그푸딩에서 나온 구체 질문 4개:
  ① 모순 vs 상태변경을 가르는 형식 기준 ② 중복 판정의 스케일 한계
  ③ 감쇠 vs 불변 사실의 구분 ④ 벤치마크 외의 메모리 품질 평가.
- 교환 성립 논리: 연구자에게 "매일 쓰는 실시스템의 문제"는 희귀 자원 —
  일방 추출이 아닌 현장 데이터 ↔ 이론 지도 교환.
- 경계: 학계 해법의 직수입 금지 (벤치마크 최적화 기준 = 과설계 위험).
  수집 대상은 답이 아니라 "내 설계가 무너질 지점의 지도".
- 이 판단의 심리적 배경(학계 트랙 유혹 차단): [게이트 착시 패턴](../personal/gate-illusion-pattern.md).
