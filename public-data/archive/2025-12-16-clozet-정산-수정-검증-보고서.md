## 발견된 문제점

### 🔴 문제 1: 취소된 주문이 정산에 포함됨

**증상:**
- 37주차 Loar 정산에 210,000원 취소 주문 포함
- 전체 20개의 취소/반품 주문이 `payment_status = 'paid'` 상태로 남음

**원인:**
```sql
-- 정산 함수가 item_delivery_status를 확인하지 않음
WHERE o.payment_status = 'paid'
  -- ❌ 취소/반품 필터링 없음!
```

**영향:**
- 과다 정산: 1,955,000원
- 브랜드 과다 지급 발생
- 정산 신뢰도 하락

---

### 🔴 문제 2: payment_status 불일치

**증상:**
- 48주차 이전: 불일치율 25.81%
- 48주차 이후: 불일치율 85.71% (악화됨!)
- 총 20개 주문이 불일치 상태

**원인:**
```typescript
// RefundManagement.tsx에서 order_items를 직접 업데이트
const { error: orderItemError } = await supabase
  .from('order_items')
  .update({
    item_delivery_status: 'cancelled',
    updated_at: new Date().toISOString()
  })
  .eq('id', selectedRequest.order_item_id);

// ❌ orders.payment_status는 업데이트하지 않음!
// ❌ 트리거와 충돌하여 payment_status 업데이트 실패
```

**영향:**
- 취소한 고객이 환불받지 못하는 상황 발생 가능
- 정산 시스템과 주문 시스템 데이터 불일치

---

### 🔴 문제 3: 'cancelling' 상태 중복

**증상:**
- `item_delivery_status = 'cancelling'` 상태가 정리되지 않음
- 데이터베이스에 중간 상태로 계속 남음

**영향:**
- 데이터 일관성 저하
- 정산 로직 복잡도 증가

UPDATE orders o

**재생성 기간:** 2025-06-30 (월) ~ 2025-12-14 (토)
**총 주차:** 25주

**재생성 스크립트:**
```sql
DO $$
DECLARE
  v_start_date DATE := '2025-06-30';
  v_end_date DATE := '2025-12-14';
  v_current_monday DATE;
  v_current_sunday DATE;
  v_week_count INT := 0;
BEGIN
  v_current_monday := v_start_date;

  WHILE v_current_monday <= v_end_date LOOP
    v_current_sunday := v_current_monday + INTERVAL '6 days';

    IF v_current_sunday > v_end_date THEN
      v_current_sunday := v_end_date;
    END IF;

    PERFORM generate_sales_settlements(v_current_monday, v_current_sunday);
    PERFORM generate_affiliate_settlements(v_current_monday, v_current_sunday);

    v_week_count := v_week_count + 1;
    v_current_monday := v_current_monday + INTERVAL '7 days';
  END LOOP;
END $$;
```
